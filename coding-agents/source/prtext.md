# prtext: PR description, title, extended description

Ziel: drei kopierfertige Texte für einen PR, geprüft am Code, nicht am PR-Text.
Der Nutzer pflegt PRs und mergt selbst. Du änderst nichts an GitHub, außer er
bittet ausdrücklich darum.

## 1. Repo und PR klären

- Gleiche PR-Nummer kann in mehreren Repos existieren. Erst im Repo versuchen,
  das zum Gespräch passt (Frontend-Reihe, Backend-Reihe); bei Treffer in zwei
  Repos den wahrscheinlicheren nehmen und das **in einem Satz** nennen.
- Lesen: `pull_request_read` get, get_diff, get_commits, get_check_runs; das
  verlinkte Issue (`Closes/Refs #N`) mit `issue_read` **immer mit lesen**.
- Bei großen oder kombinierten PRs: Repo flach klonen (`--depth=1`, per
  `add_repo`), Head und main holen, `git diff main head` lokal lesen.

## 2. Gegen den Code prüfen (nicht nur den Text)

Die PR-Beschreibung kann veraltet sein (Zwischenstände, gestrichene Teile).
Jede Zahl, jeden Default, jeden Namen, jede Behauptung ("Tests schlagen auf
altem Code fehl", "tzdata ist Dependency") gegen Diff und main prüfen. Was du
nicht prüfen konntest, wird im Text **nicht** behauptet und in den Hinweisen
benannt (lokale Testläufe, echte GPU, Browser-Sicht, Alert-Zustellung).
Prüfe außerdem:
- Repo-Regeln aus AGENTS.md / CLAUDE.md (z. B. frontend: `/design`-Katalog muss
  bei jeder Gestaltungsänderung im selben Commit mitgeändert sein: Werte fixe
  Zahlen, Fundstellen, Zeilenzahl, Status/Tip; Zahlen im Katalog nachrechnen).
- CI auf dem Head: grün? Merge-Zustand?
- Commit-Autor/Committer (Max Lechner, max.lechner@kolai.eu) und verbotene
  Trailer (`Co-Authored-By: Claude`, `Claude-Session:`, claude.ai-Links,
  "Generated by Claude Code" im PR-Body). Gefundenes melden: Footer im PR-Body
  muss der Nutzer entfernen.
- Ungültige Referenzen (`Refs #N`, das im Repo nicht existiert) und veraltete
  Zahlen im PR-Text.

## 3. Ausgabe: genau diese Reihenfolge

Zuerst kurz auf Deutsch, dann die drei Texte.

**Vorspann (knapp, deutsch):**
- *Worum es geht* (Issue, 2-4 Sätze)
- *Was wirklich gemacht wurde* (aus dem Diff, Stichpunkte, inkl. CI-Stand)
- *Wo du beim händischen Testen hinschauen sollst* (konkrete Klickwege/Aufrufe)
- *Auffälligkeiten* (Footer, falsche Refs, nicht Geprüftes, Abweichungen PR-Text
  zu Code)

Prägnant halten. Der Nutzer hat mehrfach gesagt: kürzer, nicht Text
nacherzählen, sondern den Code beschreiben.

**1. PR-Beschreibung** (ins Beschreibungsfeld des PR, nicht als Kommentar):

```
## Architectural map
### What and how
### Invariants        (✓ / ⚠ / ✗, mit dem Test genannt, der es absichert)
### Call-chain
### Where to look when X breaks
### Decisions
## Reviewer's reading guide
### Read closely
### Skim
## Verification
## Deploy impact      (explizit "None." wenn nichts)
## Non-goals
```
Englisch, Markdown, ohne KI-Footer.

**2. Titel** (PR-Titel = Merge-Titel; GitHub hängt `(#N)` selbst an):
- **beginnt mit einer Zahl** = Issue-Nummer, danach kebab-case, englisch,
  kleingeschrieben, z. B. `1321-settings-render-route-dialogs-at-the-modal-portal`
- Bei kombinierten PRs die Leit-Issue-Nummer.

**3. Extended description** (Merge-Dialog, Feld 2):
- Kurzer Commit-Body, Englisch, **hart auf 72 Zeichen umbrochen**. Nach dem
  Schreiben per Skript prüfen (`awk '{ if (length($0)>72) print NR }'`) und die
  Datei im Scratchpad ablegen; ihren vollen Pfad nennen.
- Was und warum, Abweichungen vom Standard, Breaking-Änderungen ausdrücklich
  ("Breaking: …"), Deploy-Hinweis nur wenn nötig. Keine Klassennamen-Listen.
- Footer, je Zeile eine Referenz: `Closes #N` (vollständige Lösung),
  `Related to #N` (Teil/Verwandtes), `Refs Owner/repo#N` (andere Repos).
- Kein Co-Authored-By, keine KI-Hinweise.

Alle drei Texte jeweils in einem eigenen Codeblock mit der Überschrift
"1. PR-Beschreibung", "2. Titel", "3. Extended description", damit klar ist,
was in welches Feld kommt.

## Nicht tun

- Keine Commits, keine Pushes, keinen PR-Body überschreiben, ohne dass der
  Nutzer es verlangt.
- Keine Behauptung im Text, die nicht am Code verifiziert ist.
- Keine Texte aus dem PR-Body übernehmen, ohne sie zu prüfen.
